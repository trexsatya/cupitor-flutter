# `SpeechBridge` — Speech-to-Text Integration Spec

Companion to [webapp-integration-spec.md](webapp-integration-spec.md). Read §3.2 (`AudioBridge`) there first — this channel deliberately mirrors its request/reply pattern.

---

## 1. Overview

The language webapp offers 🎤 **dictation** buttons beside the **Source** and **Target** fields of the *Add manual card* editor. Tapping one opens the microphone, streams interim text into the field as the user speaks, and appends the final transcript to whatever was already typed.

The webapp feature-detects the channel:

```js
function _haveSpeechBridge() {
  return !!(window.SpeechBridge && typeof window.SpeechBridge.postMessage === 'function')
}
```

When `SpeechBridge` is absent the 🎤 buttons are **not rendered at all** — no disabled controls, no error paths, nothing else in the editor changes. Registering the channel in the host is the whole of what turns the feature on.

**Current state:** dialog1 registers `GitHubProxy`, `TtsBridge`, `MediaState`, `AudioBridge`, `TranslateRequest`, `LinkLongPress`, `PlaylistBridge`, `NotifBridge` and `SnippetLogChannel` (`lib/main.dart` ~6849). `SpeechBridge` is not among them, so the buttons are hidden. The webapp side is complete and needs no further change.

The app already depends on `speech_to_text: ^7.0.0` and drives it in two other places (`lib/main.dart` voice input, `lib/tag_capture.dart` mask-text capture), so this is a wrapper over machinery that exists — not a new capability.

---

## 2. Transport

| Direction | Mechanism |
|---|---|
| JS → Dart | `window.SpeechBridge.postMessage(JSON.stringify(request))` |
| Dart → JS | `dialogController.runJavaScript('window.__cupSpeech(<json>)')` |

Every request carries an `rid` (request id) generated by the webapp. The reply is matched back to a pending `Promise` by that `rid`. Non-JSON payloads are silently dropped, exactly as with the other channels.

---

## 3. Request shape

```ts
type SpeechRequest = {
  op: 'start' | 'stop' | 'cancel';
  rid: string;       // e.g. "s3_m1k2j9" — opaque, echo it back
  locale?: string;   // 'start' only; absent means "device default"
};
```

## 4. Reply shape

```ts
type SpeechReply = {
  rid: string;        // the rid of the 'start' request being answered
  result?: string;    // FINAL transcript — settles the promise
  error?: string;     // error code/message — rejects the promise
  partial?: string;   // interim transcript — does NOT settle the promise
};
```

The webapp's dispatcher applies these rules in order:

1. No `rid`, or no pending request for that `rid` → **ignored entirely**.
2. `partial` present **and** `result` absent **and** no `error` → interim; the field preview updates, the promise stays open.
3. Otherwise the request settles: `error` present → reject; else resolve with `result` (a missing `result` resolves to `''`).

Because of rule 2, a reply that carries both `partial` and `result` is treated as final and the `partial` is discarded. Send them as separate envelopes.

---

## 5. Ops

| op | payload | host behaviour |
|---|---|---|
| `start` | `{rid, locale?}` | Begin listening. Stream zero or more `partial` envelopes. Settle **this** rid with the final transcript. |
| `stop` | `{rid}` | Finalise the in-flight listen so the pending `start` settles with what was heard so far. |
| `cancel` | `{rid}` | Abort the in-flight listen and discard its transcript. |

### 5.1 The rule that is easy to get wrong

`stop` and `cancel` are **fire-and-forget**. The webapp generates a fresh `rid` for them but registers no pending entry, so any reply addressed to a `stop`/`cancel` rid falls through rule 1 and is discarded.

> Both ops act on the single in-flight listen, and the host must settle the **`start`** rid — never the `stop`/`cancel` rid.

If the host answers the wrong rid (or answers nothing), the `start` promise never settles: the pending entry leaks, the button keeps its `.mee-mic-live` pulsing state, and `_speechListening` stays `true`, which blocks the other 🎤 button for the rest of the session. There is no client-side timeout.

- On `stop` → settle the `start` rid with `result: <final transcript>`.
- On `cancel` → settle the `start` rid with `error: 'cancelled'` (see §8 for why that spelling matters).

### 5.2 Auto-stop

`speech_to_text` ends an utterance on its own after a pause — the webapp never learns this happened. When the plugin's `onResult` reports `finalResult`, or `onStatus` goes `done`, the host must settle the `start` rid then and there rather than waiting for a `stop` that will not come.

**Settle on `done`, never on `notListening`.** The plugin gates `done` behind its final result, but `notListening` is emitted at end-of-speech and reaches the app *before* that final arrives — settling there truncates the transcript to its last partial. For the same reason `SpeechToText.isListening` reads false during that gap, so a watchdog polling it needs a quiet window longer than the plugin's 2 s final-result timer.

## 6. Locale

`locale` comes from the page, not from the device:

| Field | Value sent |
|---|---|
| Source | `getLangFromUrl().code` — `'sv'`, `'es'`, or omitted when the code is unknown |
| Target | always `'en'` |

These are **bare ISO-639-1 codes, not BCP-47 tags**. `speech_to_text` wants `sv-SE` / `es-ES` / `en-US`, so the host must map them — `_speechLocale()` in `lib/main.dart` already performs exactly this switch and is the natural thing to reuse. An absent or unmappable `locale` means "device default": pass `localeId: null`.

---

## 7. Microphone contention

This is where the implementation actually gets hard. On Android `AudioRecord` has a single consumer.

- **Against the host's own recorders.** `AudioBridge`'s `recordStart` and the WebView's `getUserMedia` both claim the mic. `_releaseMicFromSpeechToText()` (`lib/main.dart` ~2455) already handles the STT → recorder direction, including the 500 ms settle delay the OS needs. `SpeechBridge` needs the mirror of it: stop any native recording before calling `listen()`, and fail the `start` rather than silently recording nothing.
- **Against another STT session.** `speech_to_text` is a **native singleton** — a second `SpeechToText` Dart instance still shares one engine (see the comment at `lib/tag_capture.dart` ~799). Issue `stop()` **and** `cancel()` before `listen()`, unconditionally; both are no-ops when nothing is running.
- **What the webapp already guards.** A module-level `_speechListening` flag allows at most one dictation at a time, so the Source and Target buttons cannot both open the mic. The editor also refuses to start dictation while one of its own voice recordings is in progress, with a plain-language alert. The webapp cannot see recorders the host started on its own — that half is the host's responsibility.

---

## 8. Errors

`error` is a free-form string. It is **user-visible**: the webapp shows `alert('Dictation failed.\n' + message)` for anything that does not match `/no-bridge|cancel/i`. Keep messages short and human, not stack traces.

| Situation | Suggested `error` | Effect in the webapp |
|---|---|---|
| User cancelled | `cancelled` | Silent — field restored, no alert |
| A listen is already running | `BUSY` | Alert |
| `RECORD_AUDIO` denied | `permission-denied` | Alert |
| Engine unavailable / `initialize()` false | `speech-unavailable` | Alert |
| Mic held by a recorder | `mic-busy` | Alert |
| No speech detected | resolve with `''` instead | Silent — field restored, no alert |

"Heard nothing" is not an error. Resolve with an empty string: the webapp restores the field to its pre-dictation text and shows nothing.

---

## 9. What the user sees

Worth knowing so "final transcript" is unambiguous:

- **Given** the field already contains text, **when** dictation starts, **then** that text is captured as the base. Every `partial` renders as `base + ' ' + partial`, so the preview never eats what was typed.
- **When** the `start` settles with a transcript, **then** it is trimmed and appended the same way, and an `input` event fires so the editor's dirty-tracking notices.
- **When** the promise rejects, or the final transcript is empty, **then** the field is restored to the base text.
- The button carries `.mee-mic-live` (a pulsing animation) for exactly as long as the promise is open, and its tooltip switches to "Stop dictation". Tapping it again sends `stop`.
- Closing the editor sends `cancel` for an in-flight listen.

## 10. Reference implementation

Registration, alongside the existing dialog1 channels:

```dart
..addJavaScriptChannel('SpeechBridge', onMessageReceived: _handleSpeechBridge)
```

Reply helper, mirroring `_audioReply`:

```dart
void _speechReply(String rid, {String? result, String? error, String? partial}) {
  final payload = jsonEncode({
    'rid': rid,
    if (result != null) 'result': result,
    if (error != null) 'error': error,
    if (partial != null) 'partial': partial,
  });
  try {
    dialogController?.runJavaScript('window.__cupSpeech && window.__cupSpeech($payload);');
  } catch (_) {}
}
```

Handler sketch. `_sttRid` is the one piece of state that matters — it is the `start` rid that every reply must be addressed to:

```dart
String? _sttRid;          // rid of the in-flight 'start', null when idle
String  _sttTranscript = '';

Future<void> _handleSpeechBridge(JavaScriptMessage msg) async {
  Map<String, dynamic> req;
  try { req = jsonDecode(msg.message) as Map<String, dynamic>; } catch (_) { return; }
  final op  = (req['op']  as String?) ?? '';
  final rid = (req['rid'] as String?) ?? '';

  if (op == 'stop') {
    final target = _sttRid;
    if (target == null) return;
    try { await _speech.stop(); } catch (_) {}
    _sttRid = null;
    _speechReply(target, result: _sttTranscript.trim());   // NOT `rid`
    return;
  }

  if (op == 'cancel') {
    final target = _sttRid;
    if (target == null) return;
    try { await _speech.cancel(); } catch (_) {}
    _sttRid = null;
    _speechReply(target, error: 'cancelled');              // NOT `rid`
    return;
  }

  if (op != 'start') return;

  if (_sttRid != null) { _speechReply(rid, error: 'BUSY'); return; }

  // Free the mic: any native recording, then any lingering STT session
  // (speech_to_text is a native singleton — stop+cancel are no-ops when idle).
  await _stopNativeRecordingIfAny();
  try { await _speech.stop(); } catch (_) {}
  try { await _speech.cancel(); } catch (_) {}

  final ok = await _speech.initialize(
    onStatus: (s) {
      if (s == 'done') {                          // NOT 'notListening' — §5.2
        final target = _sttRid;
        if (target == null) return;
        _sttRid = null;
        _speechReply(target, result: _sttTranscript.trim());
      }
    },
    onError: (e) {
      final target = _sttRid;
      if (target == null) return;
      _sttRid = null;
      _speechReply(target, error: '${e.errorMsg}');
    },
  );
  if (!ok) { _speechReply(rid, error: 'speech-unavailable'); return; }

  _sttRid = rid;
  _sttTranscript = '';
  await _speech.listen(
    localeId: _bcp47(req['locale'] as String?),   // 'sv' → 'sv-SE', null → device default
    partialResults: true,
    onResult: (r) {
      _sttTranscript = r.recognizedWords;
      final target = _sttRid;
      if (target == null) return;
      if (r.finalResult) {
        _sttRid = null;
        _speechReply(target, result: _sttTranscript.trim());
      } else {
        _speechReply(target, partial: _sttTranscript);
      }
    },
  );
}
```

Note that `_sttRid` is nulled *before* every reply. That is what makes a late `onStatus` or `onError` after a `stop` harmless — it finds `null` and returns instead of settling an rid twice.

### 10.1 Where the sketch is not enough

The shipped host (`lib/speech_session.dart` for the rid rules, `lib/speech_hub.dart` for the shared recognizer, `lib/main.dart` for the I/O) differs from the sketch above in four places, each forced by `speech_to_text` 7.3.0's actual behaviour:

- **`initialize()` does not re-register its listeners.** It early-returns once it has worked, and `SpeechToText()` is a process-wide singleton — so the first speech feature to initialize owns `onStatus`/`onError` for the rest of the process, and every later registration is dropped while still returning `true`. Passing closures per `start` silently does nothing. `SpeechHub` owns the single `initialize()` and fans its callbacks out to every registered feature; each guards on its own state, since only one holds the mic at a time.
- **`listen()` does not throw when the recognizer is busy.** It returns normally, arms no timers, and delivers no callback ever. The only way to notice is a deadline: the host treats a `start` that has not gone live within 2 s as `mic-busy`.
- **`doneNoResult` is delivered as `done`, ungated, and arrives before the error.** Settling immediately on an empty `done` resolves `''` and leaves the real error to be misrouted, so the host holds an empty `done` for 400 ms to see whether an error follows.
- **Raw plugin codes are not user-facing.** `error_no_match` / `error_speech_timeout` mean "heard nothing" and must resolve `''` per §8, not alert. Everything else is mapped to a short human string.

The host also needs a mirror of `_releaseMicFromSpeechToText()`'s bookkeeping in the other direction: `AudioBridge`'s `recordStart` / `ensureMicPerm` cancel an in-flight dictation *and reply* first, because cancelling the recognizer produces no Dart callback once partials have been seen.

## 11. Test checklist

- [ ] Speak, pause, let the plugin auto-stop → the field gets the transcript, the button stops pulsing.
- [ ] Speak, tap 🎤 again to stop early → transcript up to that point lands.
- [ ] Start dictation, close the editor mid-listen → mic is released, no reply reaches a torn-down page.
- [ ] Start on Source, tap Target's 🎤 while listening → nothing happens (webapp guard), no second mic session.
- [ ] Start a voice recording, then tap 🎤 → the editor's alert appears, no `start` is sent.
- [ ] Send `start` twice from the console → the second gets `BUSY`, the first still settles normally.
- [ ] Dictate, then immediately record audio on the same face → recording works (mic actually released).
- [ ] Deny `RECORD_AUDIO` → one alert, button resets, no stuck state.
- [ ] Say nothing until auto-stop → field is unchanged and no alert.
- [ ] Existing text in the field survives a dictation, a cancel, and a failure.
- [ ] Source with `?lang=swedish` recognises Swedish; Target recognises English in the same session.
